# 단계별 시각화(발표 모드) 설계

<!-- 작성일: 2026-09-27 04:41 (KST) -->

## 의도

CNN 이 손글씨를 어떻게 처리하는지를 **발표 자리에서 한 단계씩 넘겨 보여 주는** 화면을 만든다.
지금의 웹 버전은 입력과 최종 결과만 보여 준다. 그 사이에서 무슨 일이 벌어지는지가 보이지 않는다.

**누가 보는가:** 교수와 수강생. 수현님이 화면을 조작하며 설명한다.
**언제 쓰는가:** 과제 제출과 발표. 평소 인식 용도는 기존 화면이 그대로 담당한다.
**성공은 무엇인가:** 발표 중에 "지금 보시는 그림이 실제 모델 내부입니다"라고 말할 수 있고,
청중이 28×28 입력에서 숫자 하나가 나오기까지의 흐름을 따라올 수 있다.

## 채택한 설계

**계산은 한 벌, 화면은 두 개.**

`model.js` 에 `추론_단계별()` 을 두어 각 층의 중간 결과를 함께 돌려주고,
기존 `추론()` 은 거기서 확률만 꺼내는 얇은 래퍼가 된다.
발표 화면은 `steps.html` 로 따로 만들어 `model.js` 와 `preprocess.js` 를 그대로 재사용한다.

이 구조를 고른 이유는 하나다. 발표 화면이 실제 추론과 **다른 코드로 계산하면** 그림이 거짓말을 할 수
있다. 이 프로젝트의 `CLAUDE.md` 전체가 "데스크톱과 웹의 계산이 어긋나지 않게 하라"는 경고인데,
웹 안에서 또 두 벌을 만드는 것은 같은 실패를 자초하는 일이다.

검토했다 버린 대안:
* **메인 페이지에 발표 모드 토글** — `index.html` 과 `app.js` 가 두 용도를 한 파일에서 떠안아
  복잡해진다. 발표용 큰 글씨·넓은 여백이 일상 사용과 충돌한다.
* **발표용 추론 코드 복사** — 가장 빠르지만 웹 안에 계산이 두 벌 생긴다. 위에 적은 이유로 기각.

## 화면 구성

단계는 여섯 개. 각 단계는 **그림 + 크기 표기 + 한 줄 설명**으로 이루어진다.

| # | 단계 | 보여 주는 것 | 크기 표기 |
|---|------|--------------|-----------|
| 1 | 입력 전처리 | 원본 그림 → 28×28 정규화 결과 나란히 | `280×280 → 28×28` |
| 2 | 합성곱 1 | 32장의 특징 지도 타일 | `28×28 → 26×26 × 32` |
| 3 | 합성곱 2 | 64장의 특징 지도 타일 | `26×26×32 → 24×24 × 64` |
| 4 | 최대 풀링 | 64장, 절반 크기 | `24×24 → 12×12 × 64` |
| 5 | 완전연결 1 | 128개 값 막대 | `9216 → 128` |
| 6 | 출력 | 10개 확률 막대 + 예측 숫자 | `128 → 10` |

**조작:** 이전 / 다음 단추, 키보드 ← →, 상단 단계 점처럼 생긴 표시로 직접 이동.
**그리기:** 발표 화면 안에도 캔버스를 둔다. 발표 중에 즉석에서 숫자를 그려 단계를 다시 볼 수 있어야 한다.

## 특징 지도를 그리는 방법

층마다 값의 범위가 다르다. 그대로 그리면 어떤 층은 전부 검정, 어떤 층은 전부 흰색이 된다.
**각 특징 지도마다 자기 최솟값·최댓값으로 0~255 에 펴서** 그린다. 전체 층을 한 기준으로 맞추지 않는다.
값이 전부 같은 지도(ReLU 로 전부 0)는 검정으로 둔다.

타일은 오프스크린 캔버스 한 장에 격자로 그린 뒤 화면 캔버스로 한 번에 옮긴다.
64장을 각각 DOM 요소로 만들면 모바일에서 느려진다.

## 제약

| 항목 | 값 |
|------|-----|
| 외부 의존성 | 0개. CDN·npm·번들러 금지 |
| 배포 | 정적 파일. GitHub Pages 에 파일 추가만으로 동작 |
| 계산 | `model.js` 한 벌만. 발표 페이지는 소비자일 뿐 |
| 언어 | 코드·주석·변수명·출력 메시지 한글 |
| 파일 헤더 | `작성일: YYYY-MM-DD HH:MM (KST)` |
| 기존 화면 | `index.html` 의 동작과 겉모습이 달라지면 안 된다 |

## 성공 기준

1. 발표 화면이 내놓는 확률이 메인 화면과 **완전히 같다**(같은 함수를 쓰므로 당연해야 하고, 테스트로 고정한다).
2. 여섯 단계를 끊김 없이 넘길 수 있다. 단계 전환이 눈에 띄게 멈추지 않는다.
3. `index.html` 의 기존 동작이 그대로다(회귀 테스트로 확인).
4. 발표 화면을 처음 열었을 때(아무것도 안 그린 상태)에도 화면이 깨지지 않고 무엇을 하라는지 알려 준다.
5. 노트북 화면(1280×800)에서 스크롤 없이 한 단계가 들어온다.
