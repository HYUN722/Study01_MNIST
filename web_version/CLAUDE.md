브라우저에서 바로 동작하는 정적 웹 앱입니다.
공통 규칙과 데스크톱 버전과의 관계는 상위 폴더의 `CLAUDE.md` 를 먼저 읽으세요.

## 절대 규칙

* **외부 라이브러리를 쓰지 않습니다.** CDN, npm 패키지, 빌드 도구, 프레임워크 모두 금지입니다.
  추론(합성곱·풀링·완전연결·소프트맥스)까지 전부 직접 구현된 자바스크립트입니다.
* **정적 파일만으로 동작해야 합니다.** 서버 코드, API 호출, 빌드 단계가 없어야
  GitHub Pages 에 폴더째 올려서 그대로 돌아갑니다.
* 그림과 추론은 모두 브라우저 안에서 끝납니다. 사용자의 그림을 서버로 보내지 않습니다.
* **추론 계산은 `model.js` 한 벌만 존재합니다.** `index.html`(결과만 보여줌)도
  `steps.html`(단계별로 보여줌)도 모두 `model.js` 의 `추론()`/`추론_단계별()` 을
  그대로 부르는 소비자일 뿐입니다. 합성곱·풀링·완전연결을 다른 파일에서
  다시 구현하지 않습니다 — 두 화면의 계산이 갈라지는 순간 결과도 갈라집니다.

## 파일 구조

| 파일 | 역할 |
|------|------|
| `index.html` | 결과 화면. 스크립트는 `model.js` → `preprocess.js` → `app.js` 순서로 읽습니다 |
| `steps.html` | 발표용 단계별 시각화 화면. `model.js` → `preprocess.js` → `시각화.js` → `steps.js` 순서로 읽습니다 |
| `model.js` | 순수 JS 추론 엔진 (합성곱, ReLU, 최대풀링, 완전연결, 소프트맥스). `추론_단계별()` 이 중간 결과까지 돌려주고, `추론()` 은 그 확률만 돌려주는 얇은 래퍼입니다 |
| `preprocess.js` | 캔버스 그림 → MNIST 28×28 변환 |
| `app.js` | `index.html` 의 동작: 캔버스 그리기, 결과 표시, 모델 불러오기 |
| `시각화.js` | `추론_단계별()` 의 중간 결과를 격자 타일 특징 지도(이미지)로 그리는 순수 계산·그리기 함수 |
| `steps.js` | `steps.html` 의 동작: 그림판 연결, 모델 불러오기, 여섯 단계 사이 이동, 각 단계 그리기. 계산은 다시 하지 않고 `추론_단계별()` 결과를 그리기만 합니다 |
| `style.css` | 공통 화면 꾸미기 (다크 모드 대응) |
| `steps.css` | `steps.html` 전용 꾸미기 |
| `model.bin` | 학습된 가중치. 데스크톱의 `웹_가중치_내보내기.py` 가 만듭니다 |
| `favicon.svg` | 탭 아이콘 |

## 추론_단계별() 의 반환 구조

```js
{
  확률: Float32Array(10),           // 소프트맥스를 거친 숫자별 확률
  단계: {
    합성곱1:   { 값: Float32Array, 채널: 32, 크기: 26 },  // ReLU 이후 값
    합성곱2:   { 값: Float32Array, 채널: 64, 크기: 24 },  // ReLU 이후 값
    최대풀링:  { 값: Float32Array, 채널: 64, 크기: 12 },
    완전연결1: Float32Array(128),   // ReLU 이후 값. 다른 단계와 달리 {값,채널,크기} 묶음이 아닙니다
  },
}
```

`값` 은 `(채널, 높이, 너비)` 순서로 평탄화돼 있습니다: 채널 `c` 의 (행 `r`, 열 `l`)
은 `값[c*크기*크기 + r*크기 + l]`. `시각화.js` 의 `특징지도_그리기(캔버스, 묶음, 열수)`
가 `{값, 채널, 크기}` 형태의 묶음을 그대로 받습니다. 이 구조를 바꾸면
`steps.js`·`tests/js/단계별검증.js`·`tests/js/시각화검증.js` 를 모두 함께 고쳐야 합니다.

## model.bin 형식

float32(리틀엔디언) 값이 **아무 헤더 없이** 아래 순서로 이어져 있습니다.

```
conv1.weight (32,1,3,3)   conv1.bias (32,)
conv2.weight (64,32,3,3)  conv2.bias (64,)
fc1.weight   (128,9216)   fc1.bias   (128,)
fc2.weight   (10,128)     fc2.bias   (10,)
총 1,199,882개 = 4,799,528바이트
```

`model.js` 의 `가중치_목록` 이 이 순서와 모양을 그대로 적어 두고 있고,
파일 크기가 다르면 불러올 때 바로 오류를 냅니다.
**데스크톱의 `웹_가중치_내보내기.py` 와 이 목록은 항상 같아야 합니다.**

## 구현할 때 지켜야 할 것

* **텐서 순서는 파이토치와 동일**해야 합니다.
  합성곱 가중치는 `[출력채널][입력채널][행][열]`, 완전연결은 `[출력][입력]`,
  특징 맵은 `(채널, 높이, 너비)` 로 평탄화합니다.
  풀링 후 `flatten` 도 같은 순서라 `채널*144 + 행*12 + 열` 로 색인됩니다.
* **드롭아웃은 구현하지 않습니다.** 추론 시에는 아무 일도 하지 않기 때문입니다.
* 전처리 상수(20px, 무게중심 13.5, 평균 0.1307, 표준편차 0.3081)는
  데스크톱 `utils.py` 와 한 글자도 다르면 안 됩니다.
* 큰 배열은 `Float32Array` 로 다룹니다. 일반 배열을 쓰면 눈에 띄게 느려집니다.

## 로컬에서 확인하기

```powershell
cd web_version
py -m http.server 8000
```

그 뒤 브라우저에서 <http://localhost:8000> 을 엽니다.
발표용 단계별 화면은 <http://localhost:8000/steps.html> 입니다.

> `index.html`/`steps.html` 을 파일로 바로 열면(`file://`) 브라우저 보안 정책 때문에
> `fetch("model.bin")` 이 막혀 모델을 불러오지 못합니다. 반드시 서버로 띄우세요.

## GitHub Pages 배포

저장소 설정 → Pages → Source 를 `main` 브랜치 `/ (root)` 로 두면
`https://<사용자>.github.io/Study01_MNIST/web_version/` 에서 열립니다.
빌드 단계가 없으므로 파일을 push 하면 몇 분 안에 반영됩니다.

## 성능 참고

CPU에서 한 번 추론에 약 30~80ms 가 걸립니다(1회 약 1,200만 곱셈).
첫 접속 때 `model.bin` 4.6MB 를 내려받으며, 이후에는 브라우저 캐시를 씁니다.
